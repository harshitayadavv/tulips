Type: Mobile Application Development (React Native)
How obtained: Team won sponsored problem statement by udChalo at Innerve 9.0 hackathon (Skylink project)

ABOUT UDCHALO:
udChalo is a private platform offering exclusive travel and lifestyle services to members of the Indian Armed Forces community and their families. The app serves 1M+ users.

WORK DONE:
- Built reusable UI components including carousel sections, spinning loaders, and parts of the Samsung shopping module inside the production app
- Worked on Android 15 (API level 35) migration research and compatibility documentation
- Contributed to production-level React Native features used by 1M+ users

KEY LEARNINGS:

Navigating a large codebase: Initially the hardest part was understanding a large production codebase. Unlike personal projects where Harshita built everything herself, the udChalo app had shared components, nested navigation structures, utility layers, reusable hooks, and existing architecture patterns. Even locating the correct component for a small UI behavior took time. Lesson: code organization and maintainable architecture become critical at scale.

Production code vs hackathon code: During a UI component update, Harshita implemented a quick fix using local state and conditional rendering that worked in testing. During review, her mentor explained the fix was not production-friendly — it would cause unnecessary re-renders and become hard to maintain as the feature grew. Mentor suggested a cleaner, more reusable architecture. This was the moment Harshita understood the difference between hackathon code (optimize for speed and demo readiness) and production code (maintainability, readability, scalability, long-term reliability).

Debugging across devices: A carousel component behaved differently across screen sizes and Android versions due to layout calculations and rendering timing issues. The issue was not consistently reproducible. Lesson: debug systematically, don't assume the first visible symptom is the root cause.

Remote collaboration: Most collaboration happened through implementation discussions, code reviews, and async communication. Asking questions early saves a lot of time. Discussing architecture patterns with mentors when blocked was faster than trying to trace everything alone.

Engineering mindset shift from 1M+ users: Production engineering is about reliability and maintainability, not just making things work. Small UI issues, rendering inefficiencies, or inconsistent component behavior become significant when the app is used by a very large number of users. Became more careful about reusable design patterns, performance, and the impact of even small frontend changes.

Harshita's team won the udChalo-sponsored problem statement at Innerve 9.0 with Skylink (real-time in-flight communication system). Her role was AI/ML — BERT/PyTorch moderation pipeline.
