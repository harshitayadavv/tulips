WHAT IT IS:
Tulips is a full-stack AI persona system built by Harshita Yadav. It lets anyone chat with or call an AI that represents Harshita — answering questions about her background, skills, and projects using RAG, and autonomously booking interviews on her real Cal.com calendar with no human in the loop.

PART A — VOICE AGENT:
- Platform: Vapi.ai
- LLM: Groq (llama-3.3-70b-versatile) — chosen for free tier + ultra-low latency
- STT: Deepgram nova-2
- TTS: Deepgram aura-asteria-en (free tier)
- Three custom tools: get_answer (calls /chat RAG endpoint), get_slots (calls /slots Cal.com endpoint), book_meeting (calls /book Cal.com endpoint)
- Webhook at POST /vapi-webhook on FastAPI backend routes all Vapi function-call events
- Phone number: +12542610169 (US number via Vapi free tier)
- Target latency: <2s on non-tool turns, <3s on tool turns
- responseDelaySeconds: 0 — eliminates artificial Vapi padding

PART B — CHAT INTERFACE:
- RAG pipeline: user message → embed with Gemini embedding-2 (3072 dimensions) → Qdrant vector search (cosine, TOP_K=5) → inject context into system prompt → Groq LLM generation
- Knowledge base: docs/ folder ingested via ingest.py — resume PDF, project summaries, hackathon notes, internship notes, GitHub project details
- Streaming endpoint: POST /chat/stream (SSE) for frontend
- Non-streaming: POST /chat for voice agent (voice needs complete sentence before TTS)
- Prompt injection detection with regex patterns (13 patterns)
- Booking directly from chat via POST /book (Cal.com v2)

TECH STACK:
Backend: FastAPI (Python), Render
LLM: Groq API (llama-3.3-70b-versatile)
Embeddings: Google Gemini embedding-2 (3072 dim) — google-genai SDK forced to v1 endpoint (v1beta gave 404)
Vector DB: Qdrant cloud (cosine similarity, collection: "persona")
Voice: Vapi.ai + Deepgram (STT nova-2 + TTS aura-asteria-en)
Calendar: Cal.com v2 API
Frontend: Next.js + Tailwind CSS, components: ChatWindow.tsx, BookingModal.tsx
Deployment: Render (backend) + Vercel (frontend)

BACKEND ENDPOINTS:
POST /chat — RAG chat (non-streaming), ChatRequest {message: str}, ChatResponse {response: str}
POST /chat/stream — SSE streaming chat
POST /book — Cal.com v2 booking, BookRequest {name, email, start_time (ISO8601 UTC), note}
GET /slots — Cal.com v2 slots (next 7 days), SlotsResponse {slots: list[str]}
POST /vapi-webhook — Vapi function-call router
GET /health — health check
GET /ping — UptimeRobot keepalive (prevents Render cold starts, pinged every 5 minutes)

CAL.COM V2 INTEGRATION (critical details):
Auth header: "Authorization: Bearer YOUR_KEY" — NOT ?apiKey= query param (v1 used query param, v1 is dead — 410 Gone)
Slots endpoint: cal-api-version: 2024-09-04, params: start/end (NOT startTime/endTime), eventTypeSlug
Bookings endpoint: cal-api-version: 2024-08-13, body uses attendee object {name, email, timeZone, language}
These two endpoints use DIFFERENT cal-api-version headers.

INGESTION PIPELINE (ingest.py):
Reads .txt and .pdf from docs/. Chunks by ~500 tokens with 50-token overlap (splits on whitespace boundaries). Embeds with Gemini embedding-2 (RETRIEVAL_DOCUMENT task type). Upserts to Qdrant collection "persona" (3072 dim, cosine distance). Run with: python ingest.py --wipe

DESIGN TRADEOFFS:
- Groq over OpenAI: 10x faster inference (target <500ms TTFT) at zero cost, traded model sophistication
- Gemini embedding-2 (3072d) over text-embedding-004 (768d): higher dimensional embeddings improve retrieval precision on small corpus, cost is larger Qdrant storage and slightly slower embedding calls. Also this was the only model available on the API key.
- Non-streaming for voice (/chat) vs streaming for chat (/chat/stream): voice needs a complete sentence before TTS can start, streaming adds complexity with no benefit for the voice path
- responseDelaySeconds: 0 in Vapi: eliminates artificial padding for minimum latency, slight tradeoff in "thinking time" appearance
- Qdrant cloud free tier vs self-hosted: accepted vendor dependency for zero infrastructure management

FAILURE MODES DISCOVERED AND FIXED:
1. Cal.com v1 returning 410 Gone — fixed by migrating all endpoints to v2 with correct version headers per endpoint
2. Gemini embedding model 404 on v1beta endpoint — fixed by forcing http_options={"api_version": "v1"} in google-genai client config
3. Render cold starts adding 5-10s to first voice call — fixed by adding /ping + UptimeRobot monitor at 5-minute interval
